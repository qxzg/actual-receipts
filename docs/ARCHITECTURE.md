# 小票账本实现说明

应用为 Node 24、TypeScript、Fastify、React，数据保存在 SQLite。部署目标是 `bwh-us:/opt/receipts`，网站为 `https://receipts.hx-sun.com`。两个新容器各限 512 MiB，Caddy 复用 `actual_default` 网络。

## 身份验证

- 单所有者：`owner.id=1` 数据库约束，注册完成事务再次检查所有者和会话。
- 初始化和服务器恢复令牌有效期 15 分钟，哈希存储、原子消费。首次初始化成功后关闭入口。
- WebAuthn challenge 有效期 5 分钟，绑定会话与用途，验证签名前消费。验证固定 `APP_ORIGIN`、RP ID 和用户验证标志。
- 会话为 256 位随机令牌，SQLite 仅存 SHA-256。`__Host-receipt` Cookie 开启 Secure、HttpOnly、SameSite=Lax、Path=/；普通会话 7 天。
- 写请求检查 Origin 与独立 CSRF 值；认证接口限流。敏感设置和凭据变更要求最近 5 分钟内验证。返回 428 后网页引导 Passkey 验证再重试。
- 恢复码 10 个，每个 120 位熵，单次展示与使用。受限恢复会话只能注册新 Passkey。恢复提交事务统一撤销旧密钥、旧会话和旧恢复码。
- 认证响应与私有数据禁止缓存；失败事件记录状态码，业务密码、原始令牌、模型输出均排除在日志之外。

## 金额与校验

所有金额用整数百分之一单位存储与计算。首版设置支持 USD、CNY、EUR、GBP、CAD、AUD、HKD、SGD。数量采用十进制字符串，支持称重商品。识别币种原样保留；与账本币种不同时，用户须人工换算全部金额并确认。

商品原行金额减去专属优惠后，整单优惠按比例依次分摊；税费按确认的范围分摊；税费、小费和其他费用统一使用整单折后基数。最大余数法使用 BigInt 乘除，平局按小票行顺序分配。零基数、无效范围、超额优惠、未知分类、缺失日期、金额差异均阻止提交。

## Actual 提交协议

每个草稿自带不可变提交 UUID，提交前将草稿版本、完整快照、分摊结果、目标账本指纹与父交易 UUID 写入 SQLite。重复检查范围为同一账户、日期前后一天、相同支出金额。确认令牌通过 HMAC 绑定草稿内容、版本、账本和候选 ID；队列开始写入前再次检查候选。

所有 Actual 操作通过串行的独立子进程调用官方 API。超时杀掉子进程后释放队列，阻止背景操作与后续调用重叠。写入使用稳定父交易 UUID、imported_id 和 notes 关联标识。交易创建后同步；独立临时缓存再次下载账本并核对父交易和全部子交易，完成后标记入账。

重启后，写入中任务进入待核验状态；等待写入的任务继续处理。待核验任务可从网页回读远端。用户确认重试时，先同步缓存中的未发送消息，再下载独立副本核验；发现已有标识就复用记录，发现新重复候选就保留待核验状态。Actual 规则修改明细导致回读差异时，也进入待核验。

## 图片与模型

网页逐张上传并按顺序追加到同一草稿，避免代理单次请求大小限制；追加图片使用草稿版本检查。上传流逐文件处理，真实解码检查 JPEG/PNG/WebP，拒绝多帧图片；15 MiB/张、8 张/小票、32 百万像素/张。保留上传文件和经旋转的识别预览。预览最长 12000 像素、宽度最多 1920、单张编码大小最多 3 MiB。图片读取全程要求所有者会话。

识别为持久化任务，单并发执行，保存失败原因并保留旧草稿。重新识别有覆盖确认。模型输出经 Zod 严格检查，分类按实际账本校验，税费与疑点要求用户核对。

API 模式支持 Chat Completions、Responses、JSON Schema/JSON 模式。模型从服务商 `/models` 或 Codex `model/list` 动态获取，以带中文说明的下拉列表选择；已明确为文本输入或已停用的订阅模型会被过滤。兼容服务商没有提供图片能力元数据时，界面要求图片测试确认。Codex 模式使用固定 0.153.4 的 App Server stdio 协议；每次识别启动临时进程和 ephemeral thread，关闭 shell、unified exec 和联网搜索，拒绝所有服务端工具/审批请求。仅内部认证 HTTP 路由暴露授权、状态和识别。Codex 使用只读挂载的宿主机公共 CA 根证书验证 HTTPS；Node 自带的信任根与 Rust 进程使用的系统证书存储分别配置。模型容器仅挂载独立 Codex 登录目录，不包含 Actual 凭据或业务数据目录。

成功入账后，清理队列删除原图、预览和图片引用，保留结构化明细。清理失败有退避重试和单独状态。用户删除草稿也使用清理队列。模型商留存遵循其服务设置。

## 已知运行条件

首次真实 Passkey 注册、备用密钥、ChatGPT 设备码授权需要所有者亲自完成。模型实际账号权限和识别峰值内存需在授权后测量。图片质量、长小票重叠和混合税率始终在核对页由用户确认。退货、混合付款和编辑既有 Actual 交易超出首版范围。

- [Actual 官方 API](https://actualbudget.org/docs/api/reference/)，并核验安装包 26.9.0 的实现与类型。
- [SimpleWebAuthn 服务端](https://simplewebauthn.dev/docs/packages/server)，服务器 14.0.1、浏览器 14.0.0。
- [Codex App Server](https://learn.chatgpt.com/docs/app-server)，协议按本机 Codex 0.153.4 生成类型核对。
- [Responses API](https://platform.openai.com/docs/api-reference/responses)，使用图片输入与 JSON Schema 输出。
