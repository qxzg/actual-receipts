# 小票账本实现说明

应用使用 Node 24、TypeScript、Fastify 和 React，数据保存在 SQLite。默认 Compose 将网页服务与 Codex 识别服务分成两个容器，各自使用独立持久化卷；网页服务内存上限为 768 MiB，Codex 识别服务为 512 MiB。网页服务通过使用者配置的 URL 连接 Actual。

## 身份验证

- 单所有者：`owner.id=1` 数据库约束，注册完成事务再次检查所有者和会话。
- 初始化和服务器恢复令牌有效期 15 分钟，哈希存储、原子消费。首次初始化成功后关闭入口。
- WebAuthn challenge 有效期 5 分钟，绑定会话与用途，验证签名前消费。验证固定 `APP_ORIGIN`、RP ID 和用户验证标志。
- 会话为 256 位随机令牌，SQLite 仅存 SHA-256。`__Host-receipt` Cookie 开启 Secure、HttpOnly、SameSite=Lax、Path=/；普通会话 7 天。
- 写请求检查 Origin 与独立 CSRF 值；认证接口限流。敏感设置和凭据变更要求最近 5 分钟内验证。返回 428 后网页引导 Passkey 验证再重试。
- 恢复码 10 个，每个 120 位熵，单次展示与使用。受限恢复会话只能注册新 Passkey。恢复提交事务统一撤销旧密钥、旧会话和旧恢复码。
- 认证响应与私有数据禁止缓存；失败事件记录状态码，业务密码、原始令牌、模型输出均排除在日志之外。

## 金额与校验

所有金额用整数百分之一单位存储与计算。首版设置支持 USD、CNY、EUR、GBP、CAD、AUD、HKD、SGD。数量采用十进制字符串，支持称重商品。识别币种原样保留；与账本币种不同时，用户须人工换算全部金额并确认。

商品原行金额减去专属优惠后，整单优惠按比例依次分摊；税费按确认的范围分摊；税费、小费和其他费用统一使用整单折后基数。最大余数法使用 BigInt 乘除，平局按小票行顺序分配。零基数、无效范围、超额优惠、未知分类、缺失日期、金额差异均阻止提交。

## Actual 提交协议

每个草稿自带不可变提交 UUID，提交前将草稿版本、完整快照、分摊结果、目标账本指纹与父交易 UUID 写入 SQLite。重复检查范围为同一账户、日期前后一天、相同支出金额。确认令牌通过 HMAC 绑定草稿内容、版本、账本和候选 ID；队列开始写入前再次检查候选。

所有 Actual 操作通过串行的独立子进程调用官方 API。超时杀掉子进程后释放队列，阻止背景操作与后续调用重叠。写入使用稳定父交易 UUID、imported_id 和父交易 notes 关联标识。新提交快照记录 notesFormatVersion=2，子交易备注由共享格式化函数生成；旧快照缺省为版本 1，排队写入、恢复核验和重试继续生成原备注。交易创建后同步；独立临时缓存再次下载账本并核对父交易和全部子交易，完成后标记入账。

重启后，写入中任务进入待核验状态；等待写入的任务继续处理。待核验任务可从网页回读远端。用户确认重试时，先同步缓存中的未发送消息，再下载独立副本核验；发现已有标识就复用记录，发现新重复候选就保留待核验状态。Actual 规则修改明细导致回读差异时，也进入待核验。

## 图片与模型

网页逐张上传并按顺序追加到同一草稿，避免代理单次请求大小限制；追加图片使用草稿版本检查。上传流逐文件处理，真实格式检查 JPEG/PNG/WebP 和单张 HEVC 编码的 HEIC，拒绝多帧图片；15 MiB/张、8 张/小票、32 百万像素/张。HEIC 先由 `heif-convert` 转为临时 PNG，转换设有超时，原图与临时文件在处理后删除；浏览器无法显示 HEIC 时，上传前展示文件占位。上传图片经方向校正后编码为 WebP 档案图，保留完整像素尺寸，使用 quality 92、90、88 逐级尝试、1.5 MiB 软目标及 effort 6，并移除相机元数据。达到 quality 88 后优先保留清晰度，允许高细节图片超过软目标。独立识别预览最长 12000 像素、宽度最多 1920、JPEG quality 82、单张编码大小最多 3 MiB。图片读取全程要求所有者会话。

识别为持久化任务，单并发执行，保存失败原因并保留旧草稿。重新识别有覆盖确认。模型输出经 Zod 严格检查，分类按实际账本校验，税费与疑点要求用户核对。

API 模式支持 Chat Completions、Responses、JSON Schema/JSON 模式。模型从服务商 `/models` 或 Codex `model/list` 动态获取，以带中文说明的下拉列表选择；已明确为文本输入或已停用的订阅模型会被过滤。兼容服务商缺少图片能力元数据时，界面要求图片测试确认。Codex 模式使用固定 0.153.4 的 App Server stdio 协议；每次识别启动临时进程和 ephemeral thread，关闭 shell、unified exec 和联网搜索，拒绝所有服务端工具与审批请求。内部认证 HTTP 路由提供授权、状态、识别和商品查询。Codex 镜像包含公共 CA 根证书，用于验证 HTTPS。模型容器仅挂载独立 Codex 登录目录，Actual 凭据和业务数据由网页服务管理。

### 商品补全与备注

识别分两阶段：票面提取先保留原文、商品代码、计价数量及金额，同时生成简洁商品名称和查询标记；标记为 pending 的商品再交给内部 `/enrich` 接口。两种识别来源都复用 Codex 登录查询，Codex 模式使用当前选定模型，API 模式通过账号模型列表取得默认模型。查询进程单独启用 `web_search="live"`，保持只读沙箱和现有命令、文件修改、客户端工具与审批限制。支持来源必须出现在本次打开网页事件中。

查询输入只含商家、条目 ID、名称、原文、商品代码及已知包装规格。相同原文、代码和规格在同一任务内合并查询，完成后映射回各条目。返回结果仅更新名称、单件规格、包装内件数、来源和匹配状态；购买数量、实购重量、计量单位、单价、金额、分类及分摊数据由票面和人工修改控制。来源缺失、多候选、包装冲突均标记待核对。查询失败或 210 秒超时后保留已提取的明细，用户可编辑并确认商品信息。

Item.product 为兼容旧草稿的可选元数据；新模型输出要求完整字段。quantityKind 区分 count、weight、volume、unknown，quantity 表示购买件数或实测量，unit 表示实测单位，size 表示包装内单件容量/重量，packCount 表示每包件数。旧草稿可继续打开，提交前补充数量类型。来源与票面原文可展开查看，规格编辑即时更新备注预览；每条查询疑点均有人工确认入口。

新版备注保留规范名称、已知规格和大于 1 的数量：`Diet Coke 7.5flozx10x4` 表示 7.5 fl oz/罐、10 罐/包、购买 4 包。称重备注如 `Foster Farms Free Range Chicken Thighs 3.2lb $1.40/lb`。容量缺失时包装件数使用 `10ct`；普通商品单价、税费和优惠明细保留于网页核对界面。原有已提交交易继续使用其快照对应的备注版本。

成功入账后，清理队列保留 WebP 档案图和图片引用，删除识别预览，并把仍存在的旧格式图片转换为完整分辨率 WebP。用户删除草稿或清理其他账本记录时，队列删除图片目录和关联的本地提交记录。清理失败有退避重试和单独状态。模型商留存遵循其服务设置。

每笔提交保存由 Actual 地址和 Sync ID 生成的账本连接指纹。列表通过该指纹显示当前账本历史，设置页统计其他账本的已完成记录，并在 Passkey 敏感操作验证后将选定记录加入永久删除队列。最近付款账户同样按连接指纹保存，目录接口只返回当前账本中仍有效的账户 ID。

## 运行条件

首次 Passkey 注册、备用密钥和 ChatGPT 设备码授权由所有者完成。模型权限与识别峰值内存取决于账号和部署硬件。图片质量、长小票重叠和混合税率由用户在核对页确认。首版功能范围覆盖新建单一付款账户的小票交易。
